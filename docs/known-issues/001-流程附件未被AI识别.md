# 001 - 流程附件未被 AI 识别

## 问题描述

当前审核链路中，AI 仅接收到主表/明细表字段文本和审批流文本，未接收到流程附件的文件信息或内容。这会导致涉及合同、发票、报价单、扫描件等"关键证据在附件内"的流程被误判为低风险，或给出不完整结论。

## 解决方案

### 整体架构

```
┌─────────────┐     获取文件流      ┌──────────────┐     文档解析      ┌──────────────┐
│  OA 系统     │ ─────────────────▶ │  AuraOA      │ ───────────────▶ │  MinerU      │
│  (Ecology9) │                     │  附件识别服务  │                   │  文档解析服务 │
└─────────────┘                     └──────────────┘                   └──────────────┘
```

**职责划分**：
- **OA 系统**：提供附件文件流（Base64 或二进制流）
- **AuraOA**：调用 OA 接口获取文件流，调用 MinerU 解析文档
- **MinerU**：文档解析，提取文本内容

### OA 系统侧要求

OA 系统需要提供一个 REST API 接口，根据 `docIds` 返回附件的文件流。

#### 接口规范（参考）

```
GET /api/attachments?docIds=123,124,125

返回格式：
{
  "code": 0,
  "data": [
    {
      "docId": "123",
      "fileName": "合同.pdf",
      "fileSize": 1024000,
      "fileData": "base64编码的文件内容"
    },
    {
      "docId": "124",
      "fileName": "发票.jpg",
      "fileSize": 512000,
      "fileData": "base64编码的文件内容"
    }
  ]
}
```

#### 泛微 Ecology9 实现示例

```java
@GET
@Path("/attachments")
@Produces(MediaType.APPLICATION_JSON)
public String getAttachments(@QueryParam("docIds") String docIds) {
    JSONObject result = new JSONObject();
    JSONArray data = new JSONArray();
    
    String[] ids = docIds.split(",");
    for (String docId : ids) {
        try {
            // 1. 查询附件元数据（选取最新版本）
            RecordSet rs = new RecordSet();
            rs.executeQuery(
                "SELECT imagefileid FROM docimagefile WHERE DOCID = ? ORDER BY versionid DESC LIMIT 1", 
                docId
            );
            if (!rs.next()) continue;
            
            String imageFileId = rs.getString("imagefileid");
            
            // 2. 查询文件名和文件大小
            RecordSet rs2 = new RecordSet();
            rs2.executeQuery(
                "SELECT IMAGEFILENAME, IMAGEFILESIZE FROM imagefile WHERE IMAGEFILEID = ?", 
                imageFileId
            );
            if (!rs2.next()) continue;
            
            String fileName = rs2.getString("IMAGEFILENAME");
            long fileSize = rs2.getLong("IMAGEFILESIZE");
            
            // 3. 获取文件流
            InputStream is = ImageFileManager.getInputStreamById(Integer.parseInt(imageFileId));
            if (is == null) {
                log.warn("文件流为空: docId=" + docId + ", imageFileId=" + imageFileId);
                continue;
            }
            
            byte[] fileBytes = readAllBytes(is);
            is.close();
            
            // 4. Base64 编码
            String base64Data = Base64.getEncoder().encodeToString(fileBytes);
            
            // 5. 组装返回数据
            JSONObject item = new JSONObject();
            item.put("docId", docId);
            item.put("fileName", fileName);
            item.put("fileSize", fileBytes.length);
            item.put("fileData", base64Data);
            data.add(item);
            
        } catch (Exception e) {
            log.error("处理附件失败: docId=" + docId, e);
            // 继续处理下一个附件
        }
    }
    
    result.put("code", 0);
    result.put("data", data);
    return result.toJSONString();
}

private byte[] readAllBytes(InputStream is) throws IOException {
    ByteArrayOutputStream buffer = new ByteArrayOutputStream();
    byte[] tmp = new byte[8192];
    int n;
    while ((n = is.read(tmp)) != -1) {
        buffer.write(tmp, 0, n);
    }
    return buffer.toByteArray();
}
```

**关键点**：
- **选取最新版本**：使用 `ORDER BY versionid DESC LIMIT 1` 确保获取最新版本的附件
- 接口路径可自定义（在 AuraOA 系统配置中配置）
- 返回 Base64 编码的文件内容
- 包含文件名、大小等元数据
- 异常处理：单个附件失败不影响其他附件

### AuraOA 系统侧实现

#### 0. OA 接口认证配置

由于 OA 系统通常需要认证才能访问接口，需要在系统配置中添加认证相关配置：

| Key | 说明 | 默认值 |
|-----|------|--------|
| `attachment.oa_api_auth_type` | OA 接口认证类型 | `none` |
| `attachment.oa_api_auth_token` | OA 接口认证 Token | 空 |

**认证类型说明**：
- `none`：无需认证
- `bearer`：Bearer Token 认证（Header: `Authorization: Bearer <token>`）
- `basic`：Basic Auth 认证（需要配置 username:password 的 Base64）
- `custom`：自定义 Header（格式：`HeaderName: HeaderValue`）

**示例配置**：
- Bearer Token：`attachment.oa_api_auth_type=bearer`，`attachment.oa_api_auth_token=your_token_here`
- Basic Auth：`attachment.oa_api_auth_type=basic`，`attachment.oa_api_auth_token=base64(username:password)`
- Custom Header：`attachment.oa_api_auth_type=custom`，`attachment.oa_api_auth_token=X-API-Key: your_key_here`

## 泛微 Ecology9 附件数据结构

| 表名 | 说明 | 关键字段 |
|------|------|---------|
| `workflow_billfield` | 字段定义表 | `fieldhtmltype=6` 表示附件字段 |
| `docimagefile` | 附件关联表 | `DOCID`（附件ID）、`imagefileid`（文件ID）、`versionid`（版本号） |
| `imagefile` | 附件元数据表 | `IMAGEFILEID`、`IMAGEFILENAME`（文件名）、`IMAGEFILESIZE`（文件大小） |

**附件字段存储**：主表中附件字段存储的是 `docId`（多个附件用逗号分隔，如 `"123,124,125"`）

**附件版本管理**：
- 同一个 `DOCID` 可能有多个版本（`versionid` 不同）
- 需要选取 `versionid` 最大的记录作为最新版本
- SQL 示例：`SELECT imagefileid FROM docimagefile WHERE DOCID = ? ORDER BY versionid DESC LIMIT 1`
