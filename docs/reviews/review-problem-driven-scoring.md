# 审核与归档问题定性评分验证

本清单用于真实模型回放。静态检查和请求构建测试只能证明约束被发送，不能证明模型已遵守。不得将下列预期结果当作已完成的模型验证记录。

文中的金额均为人为构造的虚拟值，不对应真实业务单据。

## 回放方式

在测试租户中分别使用严格、标准、宽松尺度，覆盖审核与归档两阶段。使用虚拟材料，采用新版提示词并保存、发布配置后执行，在 AI 调用记录中确认推理和提取实际发送的系统提示词都包含“问题定性与评分统一要求”。以下业务场景用于新版配置；重复执行评估模型波动，不要求相同分数，只要求事实认定与结论区间一致。

另外验证版本选择：升级模板后，沿用原绑定版本重审仍发送原提示词，不自动追加新评分要求；发布采用新版模板的配置并明确选择最新版本后，才使用新版提示词。记录两次的实际执行版本及调用内容，不用新版评分预期要求旧版本。

| 某条规则适用前提明确不满足，同时存在独立金额问题 | 该规则保持通过且不因此扣分；独立问题照常定性 |
| 仅非关键描述错别字，有证据确认核心事实一致 | 可通过/合规，按尺度酌情扣分或提示；不虚构资金安全问题 |
| 明确申请日期与启动日期相隔10天，规则“必须晚于，7天以上最好” | 判断满足硬性要求及建议标准，不出现“10天不足7天”，无其他时序证据不应扣分 |
| 提取输入已说明关键金额冲突未解决，却写95分通过 | 根据已有分析纠正为复核/部分合规并调整扣分，不能为了95分删去问题 |
| 提取输入仅有一般瑕疵或纯优化建议 | 不补造关键错误；区分一般瑕疵与不扣分的纯建议 |
