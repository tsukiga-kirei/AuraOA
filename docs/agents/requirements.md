# 智能体与 OA 对话 — 需求说明书

| 项 | 内容 |
|----|------|
| 状态 | 需求已确认，待实现 |
| 产品边界 | 查 + 辅助办；不回写 OA |
| 入口 | AuraOA `/chat`；OA 嵌入 `/embed/chat` |
| 维护单位 | 智能体（组合系统工具 / MCP / Skills） |

本文描述**要做成什么**。分配细则见 [allocation.md](./allocation.md)，适配器见 [oa-adapter.md](./oa-adapter.md)，运行时见 [architecture.md](./architecture.md)。

## 1. 背景与目标

AuraOA 现有能力是「选流程 → 跑一次 AI → 看结论」（审核 / 归档 / 总结）。需要补上与常见 AI 产品接近的多轮对话，但内容仍围绕 OA：**查待办与流程、辅助起草与跳转办理**。

目标：

- 用户按权限选择智能体，用自然语言完成查、辅助办。
- 平台按 **智能体** 扩展更多 OA 相关助手，而不是每个助手复制一套聊天页。
- 系统管理员控制租户可用的能力包；租户管理员在包内再分配给角色与自建智能体。
- 系统工具、MCP、Skills 从第一期就进入同一套目录、授权与可视化约定。

## 2. 范围

### 2.1 本期要做

- 智能体目录、两级分配、组织角色授权（智能体 + 工具）。
- 对话页：页内历史、Markdown、POST SSE、工具过程可视化、智能体切换。
- 内置系统工具（OA 只读 + 调用现有审核/总结 + 起草意见 + OA 跳转 URL）。
- MCP：可登记、探测、把发现的工具挂到智能体；外部服务可后接。
- Skills：按 `SKILL.md` 加载进提示词；声明的脚本可升为工具。
- 嵌入对话（当前流程上下文）。
- 会话落库与租户级保留清理；LLM 日志 `request_type=chat`。

### 2.2 明确不做

- 通过 AuraOA 在 OA 中批准 / 退回 / 转发 / 提交（适配器保持只读）。
- 归档全量检索（现有归档列表无用户范围，见 [oa-adapter.md](./oa-adapter.md)）。
- 通用闲聊、跨租户数据、系统管理员使用业务对话。
- 用对话工作台替代 `/dashboard`、`/archive`、`/summary` 的批量列表。
- 租户管理员翻看其他用户的对话全文（合规走 LLM 日志与脱敏规则）。

## 3. 角色与场景

| 角色 | 编码 | 在本功能中的职责 |
|------|------|------------------|
| 系统管理员 | `system_admin` | 维护平台能力目录；把智能体/工具/MCP/Skills **分配给租户**；租户开关、保留天数、嵌入地址、对话可用模型 |
| 租户管理员 | `tenant_admin` | 在配额内启用/组装智能体；登记本租户 MCP；启用 Skills；把智能体和工具 **再分配给组织角色** |
| 业务用户 | `business` | 使用 `/chat` 与嵌入对话；只能看见自己被授到的智能体与工具 |

### 3.1 系统管理员

- 在租户管理中为每个租户勾选可用智能体、系统工具、Skills，以及允许引用的 MCP 模板/连接。
- 未勾选的能力，该租户管理端不可见、运行时不可用。
- 分配方式对齐现有「OA 连接、主备模型、Token 配额」：平台资产由系统管理员授予租户。

### 3.2 租户管理员

- 不能把未分配的工具绑进智能体，也不能授给角色。
- 可在配额内：停用种子智能体、克隆/新建智能体、调整绑定、给不同角色不同组合（例如仅查询 vs 查询+辅助办）。
- 组织角色仍通过 `page_permissions` 控制能否打开 `/chat`；智能体与工具是额外授权，不是页面权限的替代。

### 3.3 业务用户

- 打开「AI 对话」，按有效权限选择智能体后提问。
- 看到工具卡片（待办列表、流程摘要、意见草稿、OA 跳转等），而不是只有一段模型文字。
- 「去 OA 办理」打开已有流程 URL 模板，用户在 OA 里自己点批准。

## 4. 功能需求摘要

### 4.1 智能体

- 每条智能体：`agent_code`、名称、说明、系统提示词、绑定的工具/MCP/Skills、启停。
- 种子：`oa_query`、`oa_assist`（见 [README](./README.md)）。
- 一次会话绑定一个智能体；中途切换须新开或明确确认换绑。

### 4.2 系统工具 / MCP / Skills

- 系统工具：代码注册，稳定 `tool_code`，必须声明适配器依赖与 `ui_kind`。清单见 [system-tools.md](./system-tools.md)。
- MCP：协议见 [mcp.md](./mcp.md)；授权键 `mcp:{server_code}:{tool_name}`。
- Skills：格式见 [skills.md](./skills.md)；随智能体加载，脚本工具仍要有 `tool_code` 才能授权。

### 4.3 对话与可视化

- 全局侧栏：仪表盘、工作台之下新增「AI 对话」分区，仅 `/chat` 一项；历史在页内左轨。
- 路由：`/chat/new`、`/chat/:session_id`。
- SSE：`POST` 流；事件见 [architecture.md](./architecture.md)。
- 每种系统工具独立卡片，见 [ui-visualization.md](./ui-visualization.md)。

### 4.4 与现有模块集成

- 触发审核/总结：调用现有 execute/job/SSE，对话内只展示任务卡片，不把长任务堵在同一 HTTP。
- Token：走 `AIModelCallerService`，`RequestType: "chat"`，计入租户配额。
- OA：只经适配器；租户必须已绑定 `oa_db_connection_id`，否则 OA 类系统工具返回明确错误。

## 5. 非功能

- 租户隔离：`WithTenant`；会话仅本人可读写。
- 流程实例可见性：待办中，或申请人，或审批历史出现当前用户（适配器需补齐，见 [oa-adapter.md](./oa-adapter.md)）。
- 时区：`apptime`，禁止硬编码。
- 文案：前端 i18n；注释与 Zap 中文。
- 中断：先落库占位，草稿定期保存，断开保留已生成正文。

## 6. 验收要点

- 系统管理员取消某租户的 `oa_assist` 后，该租户无法启用或把其工具授出。
- 租户管理员把 `run_audit` 从某角色去掉后，即使用户选用绑了该工具的智能体，模型也看不到、调用会被拒绝。
- 业务用户用 `oa_query` 能列出自己的待办并打开流程卡；无法读取无权流程。
- `oa_assist` 能起草意见并给出 OA URL；OA 中流程状态不变。
- 未实现的 OA 类型：对应可选能力工具显示不可用，不 panic。
- 文档：新增系统工具时同步更新本目录与 API 文档（见 [authoring.md](./authoring.md)）。
