# MCP 接入

智能体可绑定 MCP Server 上的工具，与系统工具同一套 **配额 → 再分配 → 有效集**。第一期就要能**登记、探测、把发现的工具挂到智能体**；外部进程可后接，没有外部服务时管理端仍可保存连接并显示探测失败。

## 1. 协议与传输

- 协议：MCP（JSON-RPC，`tools/list`、`tools/call`）。
- 传输第一期优先 **Streamable HTTP / SSE**，便于在 Docker 中运维。stdio 子进程列为后续（网关容器、生命周期、权限隔离成本更高）。
- 超时、最大响应体积、并发由租户/系统配置限制，避免拖死对话轮次。

## 2. 两级分配

| 层级 | 能力 |
|------|------|
| 系统管理员 | 是否允许该租户自建 MCP；最多个数；可选下发只读模板（URL 模式、协议说明） |
| 租户管理员 | 在允许时创建连接（URL、加密 Header/Token）、测试连通、刷新工具列表；把 `mcp:{server_code}:{tool_name}` 绑到智能体 |
| 组织角色 | 授予具体 MCP 工具键；未授予则对模型不可见 |

系统管理员缩小「允许自建 MCP」后，租户已有连接停用，调用拒绝。

凭据加密存储，日志禁止打印 Token。管理接口不回显密钥（对齐现有 AI Key）。

## 3. 工具命名与可视化

- 授权键与调用名：`mcp:{server_code}:{tool_name}`，`server_code` 租户内唯一。
- `ui_kind` 默认 `mcp_generic`。若未来某 OA MCP 需要专用卡片，再在目录登记覆盖，不必改协议。
- MCP 工具默认 `risk=read`；若远程工具可能有副作用，租户绑定时应能标 `assist`/`write`，**`write` 一期仍对业务用户禁用执行**（只允许登记，调用返回未开放）。

## 4. 与 OA 适配器的关系

MCP **不是** `OAAdapter` 的替代。读待办/表单仍走系统工具 + 适配器，保证权限与可见性一致。

允许的后续形态：客户把内部「OA 只读检索」做成 MCP，由系统管理员打开自建 MCP 后由租户接入。可见性不能只信 MCP 返回值：若 MCP 返回的 `process_id` 还要在 AuraOA 里展开表单，必须再走 `CheckProcessVisibility`。

## 5. 运行时

- 对话开始时：对智能体绑定的 MCP 做 `tools/list`（可短缓存），再与角色授权求交后暴露给模型。
- 调用失败：`tool_result` 带错误，不中断整个会话，由模型决定是否换工具或说明失败。
- 不把 MCP 原始系统提示泄露到租户日志全文；仅记 server_code、tool_name、耗时、成功/失败。
