# 归档复盘接口

## 归档复盘执行（JWT + TenantContext）

> 路由前缀：`/api/archive`

### 获取已归档流程列表

```
GET /api/archive/processes
```

分页查询当前 OA 用户发起或在审批历史中实际处理过的已归档流程列表，支持多维度筛选。

**查询参数**：

| 参数 | 类型 | 说明 |
|------|------|------|
| `keyword` | string | 流程标题关键词 |
| `applicant` | string | 申请人姓名 |
| `process_type` | string | 流程类型 |
| `department` | string | 部门名称 |
| `audit_status` | string | 复盘状态筛选 |
| `page` | int | 页码（从 1 开始） |
| `page_size` | int | 每页条数 |
| `start_date` | string | 开始日期 |
| `end_date` | string | 结束日期 |

---

### 导出流程列表

```
GET /api/archive/processes/export
```

按当前筛选条件导出全量归档流程为 Excel 文件。

---

### 获取归档统计

```
GET /api/archive/stats
```

返回归档复盘统计数据。

---

### 提交归档复盘任务

```
POST /api/archive/execute
```

提交单条归档复盘任务，后端异步执行。

请求可选字段 `use_latest_config` 默认 `false`。首次复盘会将最终生效的字段、规则、尺度和提示词
保存为不可变执行配置版本并绑定流程；再次复盘默认沿用原版本。只有明确传 `true` 时才升级绑定。
租户流程配置在首次发布前仅为草稿，不会进入归档复盘工作台或执行入口；首次发布生成基础配置 v1。
既有归档结果不会因管理端配置变化自动重新生成。响应中的 `config_version_no` 为实际使用版本。

### 获取任务流式输出

```
GET /api/archive/stream/:id
```

`message`（`ai_reasoning`）与 `thinking`（`deep_thinking`）事件的 `data` 均为当前尝试的累计全文，
与 `structured`、`recheck` 阶段相同，前端直接覆盖对应内容，不追加。重连会重放累计快照；
重试或切换备用模型时发送空快照，清空上一轮内容。轮询仍未提供正文时保留当前流式展示，
一旦返回已保存的正文或任务终态，则以轮询结果为准，忽略终态后迟到的推理/思考事件。
更新此协议时需同时更新 Go 服务与前端。

### 导出快照

```
GET /api/archive/snapshots/export
```

按筛选条件导出全部匹配数据为 Excel，不受当前页、`page` / `page_size` 或 5000 条上限限制。筛选条件与列表接口一致，支持：

- `columns`：自定义展示列（按参数顺序导出，前端按表格显示顺序传入；逗号分隔，如 `process_id,workflow_code,title,operator,department,process_type,compliance,audit_count,time`）
- `include_history`：布尔值（`true`/`false`），是否追加复核历史列展示当前租户内该流程的历次有效复核记录（按时间倒序），查询失败时返回错误，不生成空白历史文件

---

### 获取快照复盘链

```
GET /api/archive/snapshots/:processId/chain
```

复盘链中的每条执行记录均返回其实际使用的 `config_version_no`；迁移前历史记录可能为空，数据管理页
在“查看详情”抽屉中明确展示为未记录版本。

### 日期筛选边界

日志/快照列表及其导出接口的 `start_date`、`end_date` 按应用配置时区解释，结束日期包含当天全部记录。
实现使用 `时间 >= 开始日期零点 AND 时间 < 结束日期次日零点`，包含当天最后一秒内的微秒记录，次日边界按自然日计算以兼容夏令时。

## 查询证据

工作台结果详情增加 `query_evidence`，记录每条规则引用查询的版本、参数、数据与完整性。历史结果可能为空数组；按原结果权限访问。失败/截断信息随原有审核材料提供给 AI，由 AI 判断业务影响、评分和结论；程序不据此强制降分或改判，详见 [记忆库 / 数据记忆](./audit-data-queries.md#给审核-ai-的数据与证据)。

## 规则适用前提结果

规则结果继续使用 `passed` 表示通过/不通过。适用前提为空时沿用原校验；满足前提时校验正文；明确不满足前提时 `passed=true`，原因说明“适用前提不满足，本规则直接通过”及依据，不扣分。规则通过数量包含这些直接通过项，不新增状态。


## 反馈记忆提示词变量

审核与归档分析自动追加当前租户、业务模块和流程类型中启用的已发布反馈记忆，适用于所有新旧执行配置，无需配置提示词变量。结构化阶段仅提取前一步分析，不再次提供记忆正文或重新审核。反馈作为运行时参考资料，不能覆盖正式强制规则；实际记忆版本保留在推理调用提示词中，详见 [评论反馈记忆库](./feedback-memory.md)。

## AI 复核执行及留痕

本次绑定版本设置 `ai_config.recheck.enabled=true` 时，原结构化提取成功后进入 `rechecking`，完成后才发布最终结果、快照、通知与缓存更新。关闭或旧版本缺省时保持原两阶段。

复核默认仅接收本次绑定规则和初审结构化结果；其他业务材料、分析和原系统要求按显式变量引用扩展，不再次查询 OA、识别附件或读取新版配置。使用既有模型分配与备用模型，通过统一调用入口独立预扣及结算实际 Token；请求类型保持本业务类别，`call_type=recheck`，关联同一业务日志。与现有任务共用25分钟执行上限，现有重试、降级、取消和队列恢复机制继续适用。

任务、结果详情与历史行新增 `ai_recheck` 对象：

| 字段 | 含义 |
|------|------|
| `status` | `running`、`completed`、`failed` 或 `cancelled`；未启用时对象为空 |
| `changed` | 最终解析后的业务内容是否实际改变，键序、条目顺序和纯空白差异不计入 |
| `reuse_original` | 是否直接采用初审；为true时不重存最终副本 |
| `reason` | 模型基于证据给出的复核说明 |
| `error` | 复核未完成原因（如有） |
| `duration_ms` | 复核阶段耗时 |
| `original_result` | 初审完整结构化结果 |
| `final_result` | 通过结构与分数区间校验后的最终结构化结果，仅成功且确有变化时存在 |

原有结论、分数和结果字段表示最终采纳结果。程序只校验 JSON 结构、必要字段、规则覆盖、枚举和分数区间，不解释自然语言风险。查询失败或截断不会触发程序强制改判、改写规则结果或追加人工复核风险。未开启复核时采用初审结果，开启且成功时采用复核结果；保留现有分数与结论区间校准，不增加 AI 调用。

复核调用、空响应或输出解析/校验失败时，任务采用已验证的初审结果完成，`ai_recheck.status=failed`、`reuse_original=true`，并保留失败原因，不将技术失败认定成业务违规或复核成功。归档仍通过既有重新执行入口重跑绑定版本的完整流程；审核嵌入页另提供独立复核接口。已取消任务不再发布新结果。


## 无效 AI 结果与任务终态

- AI 返回空对象、`null`、仅含分数或缺少有效结论、分数、置信度、规则明细、风险/建议数组时，本次任务记为 `failed`，错误原因随 `error_message` 返回。合法的 0 分可以保留；缺少分数不能当成 0 分。旧 `score` 数值别名仍兼容，但显式 `overall_score=0` 不回退到别名。
- 初审结果必须覆盖本次启用的租户规则，个人自定义规则可以追加。没有有效结果时不进入可选 AI 复核，不增加 AI 调用，也不生成本次有效快照或正常完成通知；此前的有效历史快照保留。
- 规则覆盖匹配忽略作用域前缀及正文中的 Unicode 空白，容忍换行、缩进等排版差异；仍检查文字、标点与重复规则数量。已知规则 ID 优先匹配的行为保持不变。
- 失败的任务结果不生成业务评分、结论或置信度，页面展示执行失败及原因，不将技术失败展示为零分退回或不合规。
- 取消及任务后续阶段更新均只作用于 `pending/assembling/reasoning/extracting/rechecking`。对已完成、失败或已取消任务的迟到取消请求按幂等成功处理，保留原终态和历史结果。
- 归档结果还须包含有效的 `flow_audit`、`field_audit` 与总结；AI 复核可以调整核验判断和说明，但不能清空、增删或替换原有节点和字段核验对象。

### 复核沿用与流式阶段

- 无需纠正时仅返回 `{"reuse_original":true}`，成功结束并采用初审；有修改时返回 `{"reuse_original":false,"reason":"修改原因","final_result":完整结果对象}`。该表达为字段说明，完整机器结构由模板接口的 `output_instructions` 给出。
- 后端按最终业务内容再次比较。沿用或没有实际变化时不显示最终调整卡片；有变化时位于风险、改进建议之后，推理分析之前。复核错误采用初审，同时保留失败状态和原因。
- 入队时按本次绑定的不可变配置标记复核计划，启用时进度从开始就包含待复核步骤，不读取最新草稿猜测。
- SSE保留 `message`（分析增量）和 `thinking`（思考增量），增加 `structured`、`recheck` 命名事件。这两个事件的数据是当前阶段的完整累计文本，客户端替换而非重复拼接。重试/降级先发送空快照清除旧内容，成功结束刷新最后一段。
- 轮询返回可选 `structured_output`、`recheck_output`，与SSE重连共用24小时阶段缓存；仍通过原任务访问权限检查。流式内容仅用于展示，完整响应通过校验后才形成业务结果。
- 下一阶段开始产生文本时，前一输出块默认收起，可手动展开；JSON阶段按代码展示，分析阶段实时渲染安全Markdown。
